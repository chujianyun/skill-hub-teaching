# 验证与交付规则

适用于选择检查、修改测试、排查失败、准备交付或 PR。所有命令从仓库根目录执行。

## 按影响选择检查

| 改动 | 验证要求 |
|---|---|
| 仅文档或规则 | 核对文件路径、命令、引用和业务描述；不要求启动数据库或运行全套测试 |
| 前端代码或样式 | 网页类型检查、构建；涉及行为时运行相关浏览器场景，涉及布局时检查桌面与窄屏 |
| 后端代码 | 服务端类型检查、构建及相关 API 测试；若改变网页使用的行为，再验证对应浏览器流程 |
| 权限、审核、共享契约或跨端流程 | 全项目类型检查与构建，同时验证相关 API 和浏览器场景 |
| 迁移、种子或启动配置 | 在隔离环境验证初始化、重复运行和持久化，补做受影响的业务流程 |

权限、状态转换、上传校验或数据隔离发生变化时，补充能复现错误的回归用例。
复用现有测试设施，不为低影响文档或纯展示调整添加只重复实现的测试。

## 运行前提

- 先安装依赖。首次安装或共享包改变后，运行 `pnpm --filter @skill-hub/shared build`，避免消费方读取缺失或旧的 `dist`。
- API 和浏览器测试使用真实 PostgreSQL；本地数据库可用 `pnpm dev:db` 启动，需要运行中的 Docker。
- 默认专用测试库名为 `skill_hub_demo_test`；覆盖 `TEST_DATABASE_URL` 前确认它确实是可清理的本项目测试库。
- 浏览器测试使用已编译的服务端 `apps/server/dist/main.js`；先运行 `pnpm build`，不能依赖正在运行的开发服务或旧构建。
- Chromium 未安装时运行 `pnpm --filter @skill-hub/web exec playwright install chromium`。
- Playwright 默认自行启动 API 3101 和网页 5176，且不复用已有服务。端口占用时先查明所属进程，不擅自杀进程。

## 常用与定向检查

```bash
# 完整检查：按顺序执行
pnpm --filter @skill-hub/shared build
pnpm typecheck
pnpm build
pnpm test:e2e:api
pnpm test:e2e:web
```

```bash
# 前端或后端单独检查（共享包已构建）
pnpm --filter @skill-hub/web typecheck
pnpm --filter @skill-hub/web build
pnpm --filter @skill-hub/server typecheck
pnpm --filter @skill-hub/server build

# 单个 API 测试文件：按改动替换文件名
pnpm --filter @skill-hub/server test:e2e --runTestsByPath test/skill-visibility.e2e-spec.ts

# 浏览器流程文件：按改动替换文件名（先完成全项目构建）
pnpm --filter @skill-hub/web test:e2e e2e/demo.spec.ts
```

`pnpm test` 会串行运行 API 和浏览器测试，但不会替代前置构建。
`pnpm typecheck` 已包含网页表格检查；不需要在没有新改动时重复运行同一检查。

## 数据隔离与串行执行

- API 和浏览器测试默认共用测试库且会清理数据，两套测试必须串行，不能同时在另一个终端启动。
- 保留 Jest 的 `--runInBand` 和 Playwright 的单 worker 设置；若要并行，先设计每个任务独立的数据库、端口和文件目录。
- 重置工具会拒绝名称不以 `_test` 结尾的数据库。保留此保护，同时确认库的用途，不能只凭名称认定可删除。
- 不把开发 `DATABASE_URL` 直接传给测试，也不通过重置开发库修复测试失败。
- 测试上传使用临时目录，不能指向开发或持久化的 `PRIVATE_UPLOAD_DIR`。
- 测试角色通过 `apps/server/test/` 现有数据库会话辅助工具构造；不向应用增加测试登录接口。

## 失败处理与完成标准

- 先区分代码失败与缺数据库、缺浏览器、端口占用等环境问题，不通过跳过断言、放宽权限或禁用隔离保护使测试通过。
- 检查通过后，只有新改动或仍未解决的风险才需要重跑或扩大检查范围。
- 交付前检查本次文件变更，排除密钥、上传包和生成产物；保留任务开始前已有的改动。
- 完成时应满足本次需求、相关检查通过、必要文档同步；有未通过或未执行的检查时，明确标记验证缺口。
- 交付报告说明改动、实际检查与结果、未验证项及原因；不把静态阅读、历史记录或旧截图当作本次测试证据。
- 只报告实际完成的提交、推送或部署，不把拟执行动作写成已完成。

## PR 说明

仅在任务要求准备 PR 时适用；创建或发布仍遵循根文件的授权边界。

- 标题说明本次解决的问题或行为变化；正文写清原因、修改后的行为、验证结果及必要的兼容性或迁移影响。
- PR 围绕同一目标，只包含本次相关变更；不夹带已有未提交改动、无关重构或生成产物。
- 界面变化附实际验证截图；按已完成工作更新标题和正文，不把讨论过程、废弃方案或未执行检查写成成果。
